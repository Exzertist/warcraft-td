# Warcraft TD — индекс знаний

Этот файл направляет к нужному источнику. Он не хранит сами правила игры.

| Источник | Что в нём находится | Когда читать |
| --- | --- | --- |
| `../AGENTS.md` | Инструкция поведения ИИ | Перед каждой задачей |
| `../STATE.md` | Текущее состояние, проверки, блокеры, следующий шаг | Перед каждой задачей |
| `Warcraft_TD_Overview.md` | Общее видение, аудитория, платформа, режимы, основные принципы | При продуктовых и общих решениях |
| `Warcraft_TD_Design.md` | Механики, правила, числа, баланс, прогрессия, бесконечный режим | При изменении игрового процесса |
| `Warcraft_TD_Story.md` | Мир, порядок кампаний, история короля, сюжет миссий и катсцены | При работе над сюжетом и сценарием |
| `Warcraft_TD_Development.md` | Стек, этапы разработки, проверки, технические ограничения | При планировании и реализации |
| `Warcraft_TD_Modules.md` | Архитектурные модули, зависимости, контракты и владельцы данных | Перед изменением кода |
| `../WarcraftTD/README.md` | Запуск проекта и управление текущим прототипом | При запуске и ручной проверке |

## Правило единственного источника

- Одна информация должна иметь один основной источник.
- Другие документы дают ссылку, но не копируют подробное правило.
- Последнее прямое решение пользователя сначала записывается в профильный источник, затем при необходимости меняются архитектура, код и `STATE.md`.
- Временные решения прототипа записываются в `STATE.md` или `Warcraft_TD_Development.md`, но не выдаются за утверждённый игровой дизайн.

## Маршрутизация изменений

- «Какую игру делаем?» → `Overview`.
- «Как работает механика?» → `Design`.
- «Что происходит по сюжету?» → `Story`.
- «Как это реализовать и проверить?» → `Development` + `Modules`.
- «Что уже сделано прямо сейчас?» → `STATE.md`.
