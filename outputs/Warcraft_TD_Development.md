# Warcraft TD — разработка

## Технологический стек

- Unity 6000.3.24f1 / ветка Unity 6.3 LTS.
- Universal Render Pipeline 17.3.0.
- Первая целевая платформа — Android через Google Play, горизонтальная ориентация; архитектура, ввод, UI, сохранения и игровые данные должны оставаться переносимыми на другие платформы.
- Android-сборка ориентируется на актуальное требование Google Play к `targetSdk`; на 22.09.2026 это Android 16 / API 36. Минимальная поддерживаемая версия утверждена как Android 7.1 / API 25; сборка не устанавливается на Android 7.0 и старше.
- Следующие платформы добавляются через платформенные адаптеры и отдельные профили сборки после их утверждения, без копирования основной игровой логики.
- Единственная запланированная Apple-платформа — iPhone/iOS. Минимальная версия iOS выбирается перед началом этого этапа по актуальным требованиям Unity, Xcode и App Store; iPad и macOS отдельно не поддерживаются.
- Windows Player используется для быстрой автоматической проверки runtime.

Проект создаётся одним разработчиком. Поэтому приоритет имеют заменяемые данные, автоматические проверки, простые инструменты контента, зрелые открытые компоненты и минимальная собственная инфраструктура.

## Текущий вертикальный срез

Первая миссия существует как программно создаваемая greybox-сцена. Реализованы карта А→Б, камера, маршрут, волна людей-зомби, лучники, баллисты, золото, здоровье базы, три типа брони, сюжетный прорыв, паладин и открытие стен.

Текущие ключевые файлы:

- `Assets/Scripts/PrototypeGame.cs` — временный композиционный корень и несколько ещё не разделённых систем;
- `Assets/Scripts/FirstMissionFlow.cs` — сценарий первой миссии;
- `Assets/Scripts/GridPathfinder.cs` — поиск пути;
- `Assets/Scripts/CombatRules.cs` — множители урона;
- `Assets/Editor/PrototypeBuilder.cs` — сборка и автоматические прогоны.

## Материалы стартовой последовательности

Стартовая последовательность требует заменяемых ассетов: видео движка и компании, временную заглушку компании, ключевой арт и вступительную кат-сцену. Отдельно хранится флаг просмотра; правила пропуска и повтора ещё не утверждены.

До получения финальных материалов стартовую последовательность следует собирать на заглушках, не встраивая видео и изображения непосредственно в код.

## Производство ассетов

- Без найма: бесплатные модели, анимации, окружение и эффекты перерабатываются под стиль игры.
- Для стороннего материала сохраняются источник, автор и лицензия с правом изменения и коммерческого распространения; извлечённые из чужих игр ассеты без разрешения запрещены.
- Интерфейс рисует пользователь. Первая версия намеренно минимальна; новые экраны, функции и визуальные улучшения добавляются по релизам.
- Музыка создаётся бесплатными ИИ-инструментами; ранняя озвучка — через `https://web.telegram.org/a/#5526375200`. Для каждого результата сохраняются исходник и разрешение на использование.

## Собственный backend

Собственный модульный backend исполняет серверные части M15 и M17–M19. Он авторитетен для онлайн-прогресса и не допускает прямого подключения клиента к базе; микросервисы не используются без доказанной необходимости.

### Утверждённый серверный стек

`C# / .NET 10 LTS` · `ASP.NET Core Web API` · `EF Core + Npgsql` · `PostgreSQL 18.x` · `Docker Compose` · `Caddy`. Redis и очередь сообщений добавляются только при измеренной необходимости.

### Данные и файлы

- PostgreSQL хранит все доменные данные, `JSONB` карт и небольшие бинарные объекты. Крупные медиа лежат в постоянном каталоге; база хранит их метаданные и хеш.
- Полная внешняя резервная копия включает дамп PostgreSQL и каталог медиа.

### Развёртывание на компьютере владельца

- Хост: компьютер пользователя с белым IP; VMware Workstation → Ubuntu Server 26.04 LTS → Compose-контейнеры `api`, `postgres`, `caddy` и постоянные тома.
- Наружу открыты только Caddy `80/443`; API работает по HTTPS, PostgreSQL извне недоступен.
- Релиз заменяет версионированный контейнер API после резервной копии и применяет миграции; данные сохраняются. Версия API временно поддерживает предыдущий клиент.
- Доступность зависит от питания, интернета, диска и безопасности домашнего компьютера.

### Учётная запись и внутренний ID

1. Клиент получает токен Google/Apple и передаёт его backend; Play Games/Game Center остаются платформенными интеграциями.
2. Backend проверяет токен и связывает `поставщик + внешний subject` с собственным неизменяемым `PlayerID`, по которому хранится профиль.
3. Один `PlayerID` допускает несколько подтверждённых привязок; заполненные профили автоматически не объединяются.

## Правило разработки

Любая механика сначала получает владельца в `Warcraft_TD_Modules.md`, затем контракт с соседними модулями, после этого код и проверку. `PrototypeGame` нельзя расширять новой крупной системой, если её можно создать отдельным модулем.

## Git и версии

Рабочие правила Git находятся в `../AGENTS.md`. Общая стабильная ветка `main` публикуется в `https://github.com/Exzertist/warcraft-td.git`; проверенные версии отмечаются тегами `v0.x.y-<этап>`.

## Этапы

Цель первого публичного релиза — полностью завершённая сюжетная кампания людей. Содержание и количество её миссий определяет пользователь в совместной проработке обучения и сценария. Остальные кампании и крупная метаигра относятся к обновлениям после первого релиза.

### Этап 1 — устойчивый фундамент первой миссии

1. Вынести карту и координаты из `PrototypeGame`.
2. Вынести врагов и движение.
3. Вынести сооружения, экономику и волну.
4. Заменить IMGUI на отдельный UI-модуль.
5. Добавить тесты формул и маршрутов.
6. Создать редактор игровых параметров, чтобы баланс менялся через GUI и данные, а не правкой кода.
7. Отделить платформенные сервисы и ввод от игровой логики; сохранить автоматические Android- и Windows-сборки как первые профили и подготовить адаптеры Google/Apple.

### Этап 2 — завершение обучения

1. Улучшения башен 0–5 между волнами.
2. Корректный выбор разрушить препятствие или обойти.
3. Сохранение разблокировок кампании.
4. Полноценные экраны победы, поражения и перехода.

### Этап 3 — вторая миссия и герой

1. Перемещение героя.
2. Выбор одной активной способности до боя.
3. Агрессия врагов, смерть и возрождение.
4. Опыт и профиль героя.

### Этап 4 — кампания людей и первый релиз

Совместно спроектировать и реализовать все миссии людей, их обучение, сюжет, доступный контент, визуальную дугу, сохранение прогресса и выпускную проверку. Релизная версия должна пройти тестирование на физических целевых устройствах.

### Этап 5 — обновления после первого релиза

Кампании эльфов, орков, нежити и ада; метаигра; пользовательский редактор и валидация карт; сервер, недельный цикл, рейтинг, модерация, запасные карты, повторы, видео рекордов и батлпасс.

## Обязательные проверки

- C# компилируется без `error CS`.
- Windows Player собирается.
- Короткий runtime-тест завершается маркером `WARCRAFT_TD_SMOKE_OK`.
- Полный сценарий первой миссии завершается маркером `WARCRAFT_TD_MISSION_OK`.
- Изменения пути получают отдельные тесты свободного маршрута, обхода и разрушаемого препятствия.
- Формулы урона получают тесты каждой пары «атака × броня».

## Ограничение Android-сборки

В изолированном процессе Codex Java 17 не создаёт Unix-domain socket для Gradle; локальная сборка использует игнорируемую JVM-заплатку из `work` с TCP-каналом. Актуальный результат сборки хранится в `STATE.md`.
